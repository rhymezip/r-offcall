# r-offcall

> Локальные видеовстречи без облака и учётных записей — для аудиторий, кафедр, лабораторий и офисов.

**r-offcall** — лёгкое приложение для встреч людей, уже находящихся в одной доверенной локальной сети. Один компьютер становится хостом; остальные устройства обнаруживают его через mDNS и подключаются из настольного приложения или современного браузера. Камера и микрофон передаются напрямую между участниками через WebRTC, а хост координирует только состояние комнаты и установку соединений.

## Для чего проект

Университетам, офисам и лабораториям иногда нужно быстро начать встречу внутри своей сети: без создания аккаунтов, передачи данных студентов стороннему сервису и зависимости от интернета во время занятия.

r-offcall решает именно эту задачу: **небольшая встреча в доверенной общей сети**, где важнее быстрый старт и локальный контроль, чем корпоративное администрирование.

## Сценарии использования

| Сценарий | Польза |
|---|---|
| Университетская аудитория | Преподаватель открывает комнату, а студенты в той же Wi‑Fi сети подключаются без ввода IP-адреса. |
| Заседание кафедры или отдела | Небольшая группа начинает внутренний звонок без аккаунтов и облачного календаря. |
| Компьютерный класс или мастерская | Участники используют камеры, микрофоны и, в поддерживаемых клиентах, демонстрацию экрана. |
| Изолированная сеть учреждения | Встреча может продолжаться при недоступности внешних сервисов, если работает локальная сеть. |
| Временная работа на площадке | Хост создаёт комнату с паролем и модерирует участников в рамках активного сеанса. |

## Возможности

- **Автоматическое обнаружение в LAN:** хост объявляется через mDNS/Zeroconf, настольные клиенты находят его сами.
- **Прямая передача WebRTC:** аудио и видео идут peer-to-peer; хост не ретранслирует медиа.
- **Без аккаунтов и облака:** комнаты, участники и данные модерации существуют только в запущенном процессе хоста.
- **Настольный клиент и браузер:** macOS, Windows, Linux; из браузера можно открыть `http://<host-ip>:7800`.
- **Управление комнатой:** пароли, список участников, отключение микрофонов, удаление и блокировка на время работы хоста.
- **Роли для аудитории:** роли преподавателя и студента, а также необязательная информация о факультете.

## Архитектура

```text
                         локальная сеть

              mDNS-обнаружение + HTTP/WebSocket-сигнализация
┌───────────────────────────────────────────────────────────────────┐
│ Компьютер-хост                                                     │
│ aiohttp + Socket.IO · комнаты · обнаружение хоста · порт 7800     │
└───────────────────────────────┬───────────────────────────────────┘
                                │
          ┌─────────────────────┼─────────────────────┐
          │                     │                     │
     ┌────▼────┐           ┌────▼────┐           ┌────▼────┐
     │Клиент A │◄─────────►│Клиент B │◄─────────►│Клиент C │
     └─────────┘  WebRTC   └─────────┘  WebRTC   └─────────┘
```

| Трафик | Маршрут | Что происходит |
|---|---|---|
| Обнаружение | mDNS / Zeroconf | Находит хост в одной сети с поддержкой multicast. |
| Сигнализация | Клиент ↔ хост | Состояние комнат, WebRTC offer/answer, ICE-кандидаты, события модерации. |
| Камера / микрофон | Участник ↔ участник | Прямое WebRTC-медиа; хост не получает медиа только потому, что он хост. |
| Экран | Участник ↔ участник | Поддерживается настольным macOS-приложением с Qt6 и совместимыми браузерами. В Linux настольный интерфейс намеренно отключает эту функцию. |

## Плюсы и ограничения

| Плюсы | Ограничения |
|---|---|
| Не нужны аккаунты, внешний SaaS или облачный медиарелей. | Нет SSO, провайдера идентификации, аудита и постоянного управления пользователями. |
| P2P WebRTC снижает нагрузку на хост. | Mesh WebRTC подходит небольшим группам, но не заменяет SFU для больших лекций. |
| mDNS удобно находит ближайший хост. | VLAN, гостевая Wi‑Fi изоляция, VPN и блокировка multicast могут сломать обнаружение. |
| Пароли и модерация дают базовый контроль доступа. | Пароли и состояние комнаты находятся в памяти; это не корпоративная система доступа. |
| Вызовы внутри LAN могут работать без интернета. | Google STUN настроен как необязательная помощь; встречи между сетями не входят в задачу проекта. |
| Настольный клиент работает на macOS, Windows и Linux. | Демонстрация экрана в macOS требует Qt6 WebEngine. В настольном Linux-клиенте эта функция намеренно недоступна. |
| Браузерный вход легко раздать участникам. | Некоторые браузеры запрещают камеру/микрофон на обычном HTTP-адресе в LAN; используйте приложение или HTTPS. |

## Граница безопасности и приватности

r-offcall предназначен для **доверенной локальной сети**, а не для публичной или недоверенной сети.

- WebRTC защищает медиатранспорт с помощью DTLS-SRTP, но встроенная сигнализация использует HTTP и не включает TLS, SSO или управление сертификатами.
- Любой, кто может обратиться к хосту комнаты, может попытаться подключиться. Используйте пароли, контролируемую сеть и правила межсетевого экрана.
- Названия комнат, пароли, блокировки и участники хранятся в памяти и исчезают после перезапуска хоста.
- Блокировка основана на имени, а не на подтверждённой личности; её можно обойти другим отображаемым именем.
- Не открывайте порт `7800` напрямую в интернет. В проект не входят TURN, защищённая аутентификация и модель production-эксплуатации.

Как сообщить о проблеме безопасности: [SECURITY.md](./SECURITY.md).

## Требования и установка

- Python **3.10+**
- Устройства в одной доступной локальной сети
- LAN с multicast для автоматического обнаружения
- Разрешения камеры/микрофона на настольных клиентах, передающих медиа

```bash
git clone https://github.com/rhymezip/r-offcall.git
cd r-offcall
python -m venv .venv
```

```bash
# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

| Платформа | Запуск | Примечание |
|---|---|---|
| macOS | `python src/main.py` | Зависимости устанавливают Qt6 WebEngine. Подтвердите доступ к камере/микрофону и записи экрана, когда macOS попросит, затем включите демонстрацию на панели комнаты. |
| Windows | `python src/main.py` | В Windows 10/11 обычно есть WebView2. При отказе медиа включите доступ для настольных приложений в настройках приватности. |
| Linux | `python src/main.py` | Зависимости устанавливают Qt6 WebEngine. Если GUI не запускается, установите Qt/XCB runtime-пакеты вашего дистрибутива. Демонстрация экрана в настольном приложении намеренно отключена. |

## Первая встреча

1. Запустите приложение на компьютере в нужной сети.
2. Если за короткое время хост не найден, этот компьютер станет хостом на порту `7800`.
3. На стартовом экране дайте разрешения, укажите имя и роль.
4. Создайте комнату, при необходимости с паролем.
5. Остальные участники запускают приложение или открывают `http://<host-ip>:7800`.

> **Тест на одном компьютере:** вторым участником используйте вкладку браузера. Несколько настольных экземпляров делят разрешения устройств и могут конфликтовать за порт хоста.

## Настройка, проверка и развитие

| Параметр | Текущее поведение |
|---|---|
| Порт хоста | `7800` — `src/discovery.py` |
| Имя mDNS-сервиса | Уникально для каждого хоста; совпадающие имена переименовываются автоматически и не завершают приложение |
| Локальный UI-порт клиента | Начинается с `7801`; сохраняет страницу настольного клиента в loopback secure context |
| STUN | `stun.l.google.com:19302` |
| Постоянное хранение | Нет; перезапуск хоста очищает состояние комнат |
| TURN / встречи через интернет | Нет |
| TLS / HTTPS | Нет |

```bash
python scripts/verify.py
```

Команда компилирует Python-код, проверяет ответ локального статического сервера и тестирует выбор экрана в Qt без камеры и дисплея.

Для более строгих институциональных требований полезны HTTPS, ручной адрес хоста, локальная идентификация/SSO, постоянные политики и аудит, TURN/SFU и подписанные настольные пакеты.
